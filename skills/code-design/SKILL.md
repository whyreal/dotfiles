# 代码规范

## 类与模块设计

- **单一职责**：一个类 / 组件只承担一类业务能力
- **最小依赖**：禁止链式调用 `a.getB().getC()`，对外封装方法屏蔽内部结构
- **无循环依赖**：包、类之间禁止双向依赖，通过抽象或事件解耦

## 函数/方法设计

- **短函数**：单方法不超过 50 行，嵌套不超过 3 层
- **卫语句**：多层 if 用提前 return/continue 扁平化
- **参数 ≤4 个**：超过则封装为 DTO 或上下文对象
- **返回值**：禁止用数组/Map 返回异构数据，统一封装返回实体
- **条件分支 ≤5 个**：超过则用策略模式或枚举多态
- 禁止将修改响应式状态的方法作为参数传递

## 数据与常量

- **禁用魔法值**：所有固定值必须定义为常量或枚举
- **业务状态用枚举**：禁止用 int/string 判断业务状态
- **数据泥团封装**：成对出现的参数封装为值对象或 DTO

## 命名与注释

- **代码自解释**：通过规范命名表达含义，注释只写"为什么"
- **统一命名**：同一业务含义全局统一，杜绝拼音/无意义简写
- **无遗留代码**：被注释的废弃代码直接删除
- **无未使用元素**：未使用的 import、变量、方法、常量必须清理

## 架构约束

- **单向分层依赖**：视图层 → 应用层 → 领域层 → 基础设施，禁止反向/循环调用
- **无状态服务**：禁止在实例变量中存储请求上下文，通过参数透传
- **配置外置**：接口地址、超时、路径等不硬编码
- **外部依赖隔离**：数据库、DOM、第三方 API 只能放在基础设施层
- **幂等与容错**：对外接口、消息消费、定时任务必须幂等；远程调用配置超时和重试
